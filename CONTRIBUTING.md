# Contributing to OpenBacktesting

Contribute bug fixes, strategy examples, tests, documentation, translations, or improvements to the core framework and optional Studio.

- Read the [contribution guide](docs/core/contributing.md) for issues, forks, branches, pull requests, review, and sharing reproducible examples.
- Follow [local development](docs/core/development.md) to set up the core, Studio, or documentation environment and choose the relevant checks.
- Check [repository instructions](AGENTS.md) and the [Apache-2.0 license](LICENSE). Preserve third-party attribution and only submit code or data you have permission to share.

Use [Discussions](https://github.com/lucidcog/openbacktesting/discussions) for usage questions and sharing strategy examples. Report suspected vulnerabilities privately as described in [SECURITY.md](SECURITY.md). The [issue forms](https://github.com/lucidcog/openbacktesting/issues/new/choose) collect the information needed for bugs, feature requests, and documentation corrections.

Start with a focused change. For a substantial feature or compatibility change, discuss the proposed behavior in a [GitHub issue](https://github.com/lucidcog/openbacktesting/issues) before implementing it. Small corrections can go directly to a pull request. Include the problem, your change, and actual validation results; keep private data and generated runtime artifacts out of the submission.
