## Purpose

明确 Studio 的产品界面必须参考 TradingView 并以 shadcn/ui 统一基础组件，覆盖图表、编辑、设置、报告及异常状态，避免功能完成后仍以原生默认控件交付，并保证密集信息界面仍可通过键盘使用。

## ADDED Requirements

### Requirement: TradingView 参考落实到工作区结构

Studio MUST 以图表为主要工作区，提供紧凑工具栏、主副图、代码与报告区域、策略设置入口和可识别运行状态。信息密度和层级 MUST 参考 TradingView，不能只在文档中引用名称而使用无关的通用卡片页面。

#### Scenario: 用户进入策略工作区

- **WHEN** 已选择策略与数据
- **THEN** 能识别图表主区域、运行入口、参数入口、编辑区和报告区，并能在区域间切换而不丢失当前运行关联

### Requirement: 基础组件统一使用 shadcn/ui

按钮、表单、选择器、开关、标签页、对话框、菜单、提示、表格及相关基础交互 MUST 基于 shadcn/ui 组合或扩展。语义化 HTML 可用作结构，但 MUST NOT 以浏览器默认外观作为成品控件。图表和编辑器的外围控件同样遵守此规则。

#### Scenario: 新增参数设置弹窗

- **WHEN** 实现新的输入类型或设置区域
- **THEN** 基础交互复用统一组件，颜色、边框、间距和状态与现有界面一致

### Requirement: 主题与状态一致

控件、图表和编辑器 MUST 使用一致的主题与视觉层级，并覆盖正常、悬停、聚焦、禁用、加载、错误和空数据状态。盈亏 MUST 不只通过颜色表达；数值表格必须保持单位、对齐和格式一致。

#### Scenario: 切换主题

- **WHEN** 用户切换明暗主题
- **THEN** 图表、编辑器、弹窗与报告同步，用户选择可恢复，不遗留不可读颜色

#### Scenario: 参数校验错误

- **WHEN** 运行请求包含无效字段
- **THEN** 对应控件旁显示可关联错误，仍保留用户输入与其他有效字段

### Requirement: 布局调整不丢失工作状态

工作区 MUST 允许收起文件区、调整图表与底部区域比例和切换代码／报告／日志。窄窗口 MUST 提供可操作的区域切换，不让运行或保存入口无法访问。布局变化 MUST 不触发回测或丢弃草稿。

#### Scenario: 调整编辑器区域尺寸

- **WHEN** 用户改变面板高度并切换到报告
- **THEN** 草稿、图表范围和当前运行选择保留，不重新执行策略

### Requirement: 键盘与辅助技术可操作

主要操作 MUST 可通过键盘访问，对话框 MUST 管理焦点并返回触发位置，错误和忙碌状态 MUST 有可读语义。快捷键须有明确作用域；图表信息 MUST 通过详情或表格提供可读替代路径。

#### Scenario: 关闭参数对话框

- **WHEN** 用户用键盘完成或取消参数编辑
- **THEN** 焦点返回合理位置，未确认参数不被默默运行

### Requirement: 视觉要求从首版生效

首版交付 MUST 已遵守 TradingView 参考与统一组件要求，不以“后续再美化”为由保留裸控件。验证记录 MUST 如实区分静态／组件状态检查与未执行的真实浏览器验证，不能凭构建成功宣称全部交互已经验证。

#### Scenario: 汇总首版验证结果

- **WHEN** 实施报告列出 UI 完成情况
- **THEN** 列出组件与状态覆盖证据，并标明实际未执行的验证方式
