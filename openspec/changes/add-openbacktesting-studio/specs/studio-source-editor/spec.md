## Purpose

定义网页编辑器与真实本地文件之间的同步语义，保证保存冲突可见、未保存内容不丢失，并将运行所使用的精确源码版本与当前编辑状态分离，为回测结果提供可追溯的代码依据。

## ADDED Requirements

### Requirement: 编辑真实文件并保留版本

编辑器 MUST 显示实际文件内容、路径和已保存版本，独立保留未保存草稿。成功保存 MUST 写入该本地文件并返回新版本，而非只更新浏览器缓存；失败时 MUST 保留草稿。

#### Scenario: 保存策略修改

- **WHEN** 用户保存有效的文本修改且磁盘基版本匹配
- **THEN** 本地文件包含该修改，编辑器更新已保存版本并清除对应脏状态

#### Scenario: 写入失败

- **WHEN** 权限或磁盘错误导致保存失败
- **THEN** UI 显示失败，用户草稿可继续编辑，不能显示保存成功

### Requirement: 外部修改不得静默覆盖

保存 MUST 校验读取时的内容版本，检测到变化时返回冲突。外部变更发生后，干净缓冲区可刷新；有本地草稿时 MUST 保留双方内容并提供差异与显式处理动作。文件监听 MUST 不替代保存时版本检查。

#### Scenario: 外部编辑器已保存新版本

- **WHEN** 浏览器用旧基版本提交保存
- **THEN** 保存被拒绝为冲突，外部版本和浏览器草稿均保留

#### Scenario: 外部删除正在编辑的文件

- **WHEN** 磁盘文件被删除而浏览器仍有草稿
- **THEN** 显示删除状态，不能自动重建文件或丢弃草稿

### Requirement: 保存与运行按固定顺序执行

`Save & Run` MUST 先成功保存，再从固定源快照发现并校验配置，最后提交执行；任一步失败 MUST 不继续启动回测。仅修改参数时可直接运行，输入变化 MUST 不隐式改写 Python 默认值。

#### Scenario: 保存后发现语法错误

- **WHEN** 文件保存成功但策略模块存在语法错误
- **THEN** 磁盘保留用户保存的内容，显示定位诊断，不创建正在执行的成功任务

#### Scenario: 保存冲突阻止运行

- **WHEN** `Save & Run` 的保存步骤冲突
- **THEN** 不提交新运行，用户先处理冲突

### Requirement: 运行源码快照完整且稳定

每次运行 MUST 使用固定入口和明确捕获的本地依赖集合，保留目录结构、内容摘要与来源映射。捕获期间检测到变更 MUST 重试或失败，不能混用不同版本。未捕获的外部依赖 MUST 明确记录复现限制。

#### Scenario: 排队后源文件变化

- **WHEN** 任务已入队而用户继续修改原策略或本地依赖
- **THEN** 原任务仍使用已绑定快照，新代码只能进入新的运行

#### Scenario: 动态导入本地模块

- **WHEN** 策略执行时动态导入已配置源根内的 Python 模块
- **THEN** 加载运行快照中的该模块，而非工作区随后变化的内容

### Requirement: 当前编辑状态与历史结果可区分

编辑器与报告 MUST 显示所关联的源码版本；当前文件或配置变化时，旧结果 MUST 标识过期且保留原运行身份。历史诊断定位到与该运行对应的源码，不能错误高亮已变化文件的同一行。

#### Scenario: 查看旧错误定位

- **WHEN** 用户在修改源码后点击旧运行的错误行
- **THEN** 打开对应快照或明确提示版本差异，不把旧行号当作新文件的准确位置
