## Context

动机与范围见 [proposal.md](proposal.md)。依据 [字标研究](../../../../docs/research/openbacktesting-wordmark-design.md)，采用原创几何粗字标；研究中的权重、字距和尺寸均是试验起点。

当前 Studio 使用 IBM Plex Sans 和 Activity 图标，顶栏高 48px；Docs 使用系统字体、通用图标及独立页头模板。`studio/web/index.html` 尚无 favicon 声明。Docs 的实际内容根目录为 `docs/core/`，共享资源通过 `scripts/docs_site.py` 纳入站点。README 包括根目录、七种语言版本及 `studio/README.md`。`docs/core/_static/studio/` 中七张现行截图需要逐一检查旧品牌露出。

## Goals / Non-Goals

**Goals:**

- 同一字形在 Studio、Docs 和 README 中稳定渲染；主题只改变配色，不改变品牌形状。
- 长名称在真实导航空间中可读，品牌不得挤占操作按钮；辅助技术仍能识别产品名称。
- 资产可追溯、可维护、随现有构建分发，加载品牌无需远程服务。

**Non-Goals:**

- 不更换界面正文字体，不改包名、API、运行协议及回测行为。
- 不重画赞助商标识、TradingView 归因或 vendor 素材，不修改历史归档截图。
- 不在本阶段实施、不自动发布 Docs，不将品牌设计扩大为全站改版。

## Decisions

### 1. 先确定字形，再完成跨入口接入

以 Manrope 750–800 为基础，单行、同色、保留 `OpenBacktesting` 大小写和默认双层 `a`。使用 Inter 700–750 对照，确认 Manrope 在小尺寸的表现。先比较原生字距及 `0`、`-0.01em`、`-0.02em`，重点光学校正 `nB`、`kt`、`st` 和尾部 `ing`，不横向压缩字形。黑白版本先通过验证，再评估现有品牌蓝。

在 16/18/20px 可见字形高度与 160/180/200px 预留宽度中实测；这些是样张范围，不是已承诺的最小尺寸。README 同时检查 32/48px 字形高度。最终记录选定参数与推荐最小尺寸，无需再次为例行设计选择请求批准。字标旁的 `Studio`、Docs 副标题保持独立布局。

### 2. 以轮廓矢量作为共享资产来源

建议在 `docs/assets/brand/` 保存规范字标、黑白版本、紧凑标识、favicon、来源与导出说明。字标使用轮廓路径，避免依赖客户端字体、远程字体和 SVG 内嵌脚本；品牌展示不引入新的运行时字体依赖。生产导出前锁定字体版本或提交与摘要，保存对应授权；如保存字体文件，必须随附其许可证和声明。

Studio 通过构建导入或确定性复制接入，Docs 通过现有构建钩子纳入 `_static/brand/`。派生副本不得人工分别修改，必要时增加窄范围同步检查。README 直接引用仓库共享资产并使用相对路径；不将品牌 URL 指向尚未部署的资源。方案比各处使用普通文字更能保证一致，也避免重复维护多个独立 SVG。

### 3. 紧凑标识只服务尺寸受限场景

favicon 与完整字标无法容纳的导航空间采用由同一字形语言提炼的 `OB` 紧凑标识，独立校正其小尺寸笔画与间距，不沿用 TradingView 符号或 Activity 折线。它仅用于紧凑入口，正常宽度保留全称，辅助技术名称始终为 `OpenBacktesting`。在 16/32px 检查 favicon；切换阈值依据实际可用空间确定，不能仅依赖把全称不断缩小。

### 4. 展示清单明确覆盖边界

| 入口 | 实施方式与完成条件 |
| --- | --- |
| Studio 顶栏 | 替换 Activity 与普通品牌文字，保留 `Studio`，核对路径截断及右侧控件；不新增会重置工作区的品牌点击行为。 |
| Studio 浏览器标签 | 配置同源 favicon，保持标题和本地离线运行能力。 |
| Docs 页头及 favicon | 替换通用图标与普通品牌主标题；品牌链接仍返回首页，保留搜索、主题、抽屉、赞助及副标题行为。 |
| 根 README 与七种语言 README | 添加适配明暗背景的字标及可靠回退，路径按各文件位置计算，保留语义标题和语言导航，避免标题与大字标重复抢占首屏。 |
| Studio README | 使用同一资产和独立 `Studio` 描述，不另设品牌。 |
| 当前文档截图 | 检查七张截图，重新从真实产品捕获含旧字标的图片；保留对应工作流的说明价值，不把新 Logo 覆盖到旧截图上。 |
| 其他第一方入口 | 检索品牌图像、页头和 favicon；将实际发现项纳入清单，注明替换或保留理由。普通段落、示例说明和测试夹具名称不是 Logo。 |

文档截图不属于数值或协议基线；更新时仍需检查截图内容与现有说明一致。第三方及历史素材明确标记为保留，不以全文替换处理。

### 5. 响应式与无障碍是接入约束

完整字标与紧凑标识保持宽高比；主题采用 `currentColor` 或明确黑白资产，避免白底白字、深底黑字及闪现错误颜色。README 可用 `<picture>` 配合主题媒体条件和默认 `<img>`，同时验证不支持主题选择时的回退。保留语义标题、可访问名称和首页链接焦点；同一品牌的装饰图片不重复朗读。资源包含尺寸，避免加载造成明显布局跳动。

### 6. 浏览器验收按本次需求限定范围

用户明确要求浏览器验收，且仓库开发指南要求 UI 变更经过真实浏览器检查，因此该步骤为实施完成条件。使用构建后的真实 Studio host 和 Docs 预览，不以 Vite 空壳代替完整应用，不绕过会话安全。README 使用实际仓库 Markdown 渲染预览并记录渲染器；若未检查 GitHub 原生渲染，不声称已通过 GitHub 验收。

- 在 1440、768、375、320 CSS px 宽度检查 Studio 与 Docs，覆盖明暗主题；代表性的桌面/窄屏检查 200% 缩放，字标样张检查 1×/2× 像素密度。
- 检查完整字标或紧凑标识清晰、无裁切或新增横向溢出、相邻操作可用、主题切换同步、资源无缺失及无需额外远程品牌请求。
- Docs 检查首页与一个嵌套页，确认品牌返回首页、搜索及移动抽屉仍可用；Studio 检查文件侧栏、策略路径和运行按钮布局。favicon 验证文档引用、响应和实际标签图标。
- README 检查根目录、一个非中文译本、中文译本及 Studio README 的明暗预览，其余译本检查资产路径与共享结构；不为此推送或发布仓库。
- 保存有限截图、环境、页面、主题、视口及结论，完成展示清单；失败时修复并重验。不得仅以文件存在或截图生成成功判定视觉合格。

验证优先使用相关静态检查及构建；最终按项目要求运行 `uv run --locked python scripts/verify.py --profile full`，因为跨文档、前端共享资产需要确认包内资源。复用现有浏览器基础设施，不为静态 Logo 扩展无关回测旅程或新增测试框架。

## Risks / Trade-offs

- 长名称在高字重下糊成一条 → 以实际大小验证，必要时调整紧凑版本字重与光学间距，不强行缩放。
- README 渲染器主题支持不同 → 提供明确回退并记录实际检查的渲染器，保留可读文本。
- Docs 与 Studio 构建遗漏共享资源 → 验证构建输出及安装产物中的资产，不只验证源码引用。
- 修改图片造成文档场景失真 → 真实重拍对应状态，检查文案与截图对应关系，避免暴露本机敏感路径。
- 紧凑 `OB` 的辨识度尚未实测 → 仅在受限位置使用，保留完整可访问名称，并与完整字标并排评估。

## Migration Plan

先产出可审阅样张并确定主资产，再逐项接入展示清单，重拍受影响截图，完成构建与浏览器验收。更新中文实施记录时同步精确摘要。变更不需要数据迁移；如需回退，恢复旧引用及样式并重新构建两个展示端，不修改交易数据或 vendor 文件。此处完成的是仓库替换与本地验证，线上部署状态应单独报告。

## Open Questions

最终字重、光学字距、紧凑模式阈值和推荐最小尺寸由样张及实际页面决定；均不改变本方案范围和规范契约。
