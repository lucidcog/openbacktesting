## Purpose

定义本地回测从固定请求、入队、执行、取消到终态恢复的完整生命周期，确保任意运行有可追踪的身份和真实状态，失败或迟到响应不会污染已展示的结果，且宿主在策略异常时仍可操作。

## ADDED Requirements

### Requirement: 请求身份与幂等提交

运行请求 MUST 固定源码、输入 schema、覆盖值、有效设置、数据来源快照、上下文和环境身份，并分配唯一运行 ID；实际加载的数据身份 MUST 在策略执行前确定并固定。相同幂等键与相同请求 MUST 返回原任务；同一键用于不同请求 MUST 拒绝。

#### Scenario: 网络重试提交

- **WHEN** 客户端重发同一个已接受请求
- **THEN** 返回原 run ID，不重复执行策略

#### Scenario: 过期 schema 请求

- **WHEN** 固定源码描述与请求 schemaHash 不符
- **THEN** 在策略生命周期开始前拒绝请求，并返回 schema 差异错误

### Requirement: 有界队列与真实进度

宿主 MUST 提供有界队列和可见排队顺序，达到上限时明确拒绝。界面 MUST 展示实际阶段，不得在框架没有进度证据时虚构完成百分比。

#### Scenario: 队列已满

- **WHEN** 用户在队列达到配置上限后提交新任务
- **THEN** 返回队列满错误，既有任务不被偷偷替换或丢弃

#### Scenario: 框架只提供开始与结束信息

- **WHEN** 策略正在执行且没有逐步进度回调
- **THEN** 显示运行中阶段和已用时间，不显示虚构的 K 线处理百分比

### Requirement: 每次运行使用新进程与同一结果

每次运行 MUST 使用新受管进程和独立日志会话，通过公开运行时执行。Portfolio 和 PlottingResult MUST 从同一个回测结果生成，不能为了图表另跑一次。策略模块、全局变量和实例 MUST 不跨运行复用。

#### Scenario: 连续运行修改后的模块

- **WHEN** 两次运行使用不同源码版本
- **THEN** 第二次不会因 Python 导入缓存使用第一次的模块状态

#### Scenario: 非确定性策略导出图表

- **WHEN** 策略本次运行产生随机结果
- **THEN** 报告与图表使用该次运行事实，不因额外重跑而不一致

### Requirement: 终态与持久化一致

运行 MUST 明确区分 queued、running、cancelling、succeeded、failed 和 cancelled。成功 MUST 以必要报告完整保存为前提；提前终止数据范围 MUST 单独披露。终态 MUST 不被迟到事件改写。

#### Scenario: 计算结束但必要报告保存失败

- **WHEN** 产物持久化发生磁盘错误
- **THEN** 运行不显示为可读取的成功结果，错误和可恢复诊断保留

#### Scenario: 框架有效返回但提前终止

- **WHEN** 引擎在请求范围结束前终止并返回有效 Portfolio
- **THEN** 可以记录成功导出，但报告显示实际执行范围和终止原因，不能声称完整区间已执行

### Requirement: 取消具有确定的竞争规则

取消 MUST 对排队和运行中任务生效，并以宿主接受取消或提交成功终态的先后决定结果。接受取消后 MUST 阻止迟到成功发布；工作进程仍在执行时 MUST 不声称取消完成。宽限期后必须能够终止受管进程树。

#### Scenario: 取消排队任务

- **WHEN** 任务尚未开始就被取消
- **THEN** 转为 cancelled，策略和 loader 均不因该任务执行

#### Scenario: 取消先于成功提交

- **WHEN** 宿主已接受取消，随后收到工作进程的成功结果
- **THEN** 该结果不能发布成当前成功终态，任务在进程回收后记录为 cancelled

#### Scenario: 成功先于取消

- **WHEN** 成功结果已完整提交后再收到取消请求
- **THEN** 保留 succeeded 并告知任务已结束，不删除结果或改成取消

### Requirement: 错误与日志如实保留

运行 MUST 区分导入、校验、执行、导出和保存错误，保留可获取的结构化日志及 stdout／stderr。日志 MUST 有大小边界，截断或强制终止导致缺失时明确说明；任意文本 MUST 以文本展示。

#### Scenario: 策略写日志后抛出异常

- **WHEN** 策略运行失败且已产生可获取日志
- **THEN** 显示失败阶段、错误位置及这些日志，不用空白界面替代诊断

#### Scenario: 强制终止丢失缓冲日志

- **WHEN** 进程被终止且部分日志未传回
- **THEN** 标记日志可能不完整，不能把已获取尾部称为完整输出

### Requirement: 宿主重启恢复可解释

宿主重启 MUST 保留已完成运行，识别未完成记录并标记中断原因，不自动重跑，不假装已恢复无法验证的进程。旧客户端事件 MUST 不覆盖新实例状态。

#### Scenario: 执行中宿主退出后重启

- **WHEN** 索引中存在上次实例的非终态运行
- **THEN** 将其标为中断失败并保留可用产物，用户显式提交后才开始新运行
