## Purpose

约束 Lightweight Charts 完整源码的引入、构建、修改与升级，使 Studio 真正使用可维护的本地图表实现，能够补齐产品所需能力，并保留可信的上游来源、分发声明与修改证据。

## ADDED Requirements

### Requirement: 引入时核验最新稳定完整源码

实现 MUST 在实际引入时核验官方最新稳定版，固定到具体 tag 和 commit，并纳入该提交的完整文件树。MUST 保留源码、测试、文档、构建配置和许可证，不能只复制压缩产物或选择性摘取实现。

#### Scenario: 研究版本不是实施时最新版本

- **WHEN** 开始引入时官方已有更新稳定版
- **THEN** 以重新核验的稳定版为基线并记录来源，不能把研究报告中的旧版本直接宣称为最新

#### Scenario: 审核来源清单

- **WHEN** 将导入清单与上游固定提交比较
- **THEN** 文件覆盖、内容摘要和本地修改记录可核对，无未解释缺失

### Requirement: 运行产物必须来自本地源码

Studio MUST 从仓库内图表源码构建并使用其产物，不能误用 npm、CDN 或缓存中的未修改版本。运行产物 MUST 能追溯到上游版本和本地修订。

#### Scenario: 本地修改影响图表行为

- **WHEN** 某项图表能力在本地源码中被补齐并完成构建
- **THEN** Studio 使用包含该修改的产物，版本信息能够确认其来源

### Requirement: 上游限制不得替代功能交付

已确定的 Studio 图表需求 MUST 完整实现。现有 API 或图元机制不足时 MUST 修改本地源码补齐；未实现提示、形状替换、精度丢失或永久降级 MUST NOT 作为需求完成。

#### Scenario: 原生形状缺少三角标记

- **WHEN** 输入契约要求精确三角形而原生标记不具备
- **THEN** 通过扩展或源码修改实现对应形状，不能以箭头替代后宣称完全支持

### Requirement: 本地修改与上游升级可审查

每项本地修改 MUST 记录目的、涉及语义和回归证据；上游升级 MUST 保留本地行为并经显式审查，不能直接覆盖修补。相关上游测试 MUST 保留，不能删改断言来掩盖不兼容。

#### Scenario: 上游更新覆盖修改区域

- **WHEN** 合入新版本时与本地实现冲突
- **THEN** 解决冲突并验证原能力仍在，失败时保留原稳定版本而不发布不完整升级

### Requirement: 许可证与原文完整保留

纳入和分发 MUST 保留适用许可证、NOTICE、版权信息和必要署名链接。第三方原文 MUST 不为项目语言默认策略被批量改写；来源与本地新增内容需要可区分。

#### Scenario: 检查安装包中的图表资源

- **WHEN** 检查 Studio 分发包和界面署名
- **THEN** 所需声明与 TradingView 链接齐全，使用本地源码不被当作取消署名的理由

### Requirement: 源码纳管与安装体积分离

完整上游源码 MUST 留在开发仓库；用户运行包 MUST 仅包含运行所需构建产物及必要声明，不要求安装上游文档、开发工具链或测试资源才能启动。

#### Scenario: 无开发工具运行

- **WHEN** 用户仅安装 Studio 运行包
- **THEN** 修改后的图表能力可用，不需要自行编译或下载完整上游工程
