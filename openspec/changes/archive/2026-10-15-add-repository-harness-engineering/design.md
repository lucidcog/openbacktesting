## Context

动机及范围见 [proposal.md](proposal.md)。当前为同仓双 Python 分发包：core 使用根 `uv.lock`，Studio 使用含本地 core source override 的独立锁文件；Studio 必须先构建前端资产，再安装其开发环境。现有开发指南已列出检查命令，不应再复制一套维护规则。

当前有 47 个 core 测试模块、12 个 Studio Python 测试模块和 22 个前端测试文件；数量不代表覆盖率。HTTP 集成测试会执行真实 worker，但前端交互测试替换了图表、编辑器或 API。CLI 支持 `--port 0`、`--no-open`；宿主、工作区锁、快照、结构化错误和运行产物可以复用。当前没有第一方 CI，远端 required checks 状态未知。

本次研究执行的语言检查发现 19 个失效文件例外与 2 个失效文本例外。历史 OpenSpec 删除属于既有提交；实施时只删除确已失效的登记，不恢复整套旧规范。本次新建计划和研究报告继续以精确路径、SHA-256 和英文理由登记。

## Goals / Non-Goals

**目标：**

- 同一检查定义驱动本地和 CI，输出可被代理读取且能复核的结果。
- 把“未执行”“环境失败”“断言失败”和“通过”分开，任何必需项未通过都不能伪装成成功。
- 在独立数据、进程和浏览器上下文中验证三条真实 Studio 旅程。
- 只强制已确认的少量架构不变量，以明确的证据记录维护债务。

**非目标：**

- 不改变交易算法、产品契约或依赖版本策略，不构建模型执行平台。
- 不引入新日志服务或遥测后台，不把所有风格偏好变成强制门禁。
- 不扩大为多浏览器兼容矩阵、全面视觉快照基线或 Windows 支持承诺。
- 不自动推送、创建 PR、合并、发布或修改远程分支保护；维护任务产出本地或 CI 可审阅候选修复说明。

## Decisions

### 1. 保留现有事实来源，新增薄入口

`AGENTS.md` 只提供模块地图、验证入口和关键不变量的链接。新增英文 `docs/core/harness.md` 描述检查协议、责任和反馈流程；`docs/core/development.md` 继续承载环境与开发命令，`mkdocs.yml` 增加维护导航。维护角色统一为维护者与变更作者，不虚构人员名单。

设计时的研究结论曾保存于 `docs/research/`；该目录已于 2026-10-15 按用户要求删除。本变更实施完成后归档至 `openspec/changes/archive/`，按用户要求跳过主 spec 同步，不恢复此前删除的规范。文档区分手写源、模板、生成 reference、历史证据与当前要求；对新旧计划明确状态。

替代方案是扩大 `AGENTS.md` 或新增第二套开发手册；这会重复规则并制造漂移，因此不采用。

### 2. 用 Python 标准库编排验证，不复制测试逻辑

新增 `scripts/verify.py`，命令接口为 `python scripts/verify.py --profile <docs|core|studio|full>`；省略 profile 等同于 `full`，不依据路径自动猜测范围。检查定义集中在仓库内的 Python 数据结构，包含稳定 ID、所属 profile、命令参数数组、工作目录、前置依赖、超时与产物位置。使用参数数组启动进程，不拼接 shell 字符串。

环境准备、检查和构建分别记为阶段。uv、npm、浏览器依赖缺失必须给出可执行的准备命令并失败；不得静默少跑。准备命令锁定现有 lockfile，禁止自动更新锁文件。CI 和本地复用同一准备说明及入口。

| profile | 必需检查与边界 |
| --- | --- |
| `docs` | 语言与包完整性检查、指标及 reference 漂移、严格文档构建、文档链接与示例相关测试、维护入口检查；不要求 Node 或浏览器 |
| `core` | 语言与包完整性、架构检查、根 pytest、包自检、公开接口及结果契约回归、生成物漂移；使用根锁文件，不安装 Studio |
| `studio` | 语言检查、适用架构检查、vendor 身份、schema 漂移、Python host 测试、前端 typecheck/lint/Vitest/build、三条 E2E；先构建 web，再同步 Studio 锁文件 |
| `full` | 以上检查按 ID 去重，再执行双包构建、分发完整性及独立安装检查；从项目元数据读取版本，不硬编码产物文件名 |

`docs` 的示例相关测试使用根 `test` extra；它不是不安装 Python 依赖的轻量文字检查。纯文字局部修改仍可按指南执行更窄命令，但不得将其报告为完整 profile 通过。slow ML examples 保留现有显式环境开关；默认排除的检查类别写入结果的 `excludedChecks`，不能声称默认 `full` 覆盖所有可选慢测试。文档浏览器工具测试若要求 Node，留在具备 Node 的 `studio`／`full` 阶段，不改变 `docs` 的无 Node 契约。

检查图顺序执行有依赖的步骤；一个阶段失败后，依赖它的检查标记为 `blocked`，无依赖检查可继续收集问题。超时或取消必须停止该次启动的进程组，最后保存部分报告。默认不自动重试；人工重跑记录为新的 attempt，不能覆盖第一次失败。

替代方案是 Makefile、npm scripts 或 CI YAML 各自编排；统一 Python 入口可以保持 core 开发不依赖 Node，并避免同一检查在多个入口产生差异。

### 3. 明确“只读检查”及结果协议

只读指不修改受版本控制的源文件、锁文件、已审阅 fixture、schema、manifest 或基线；构建可以写现有忽略目录，报告写 `.verification/harness/<run-id>/`，不意味着完全不写磁盘。运行前后比较受保护文件字节与新增源文件，保留运行前已有未提交改动；发现额外变动则失败并报告，不自动 reset 或恢复用户文件。

输出 JSON 使用 `schemaVersion: 1`，包含 `runId`、提交及 dirty 状态、profile、平台／解释器／工具版本、锁文件摘要、起止时间、总状态、排除项和 `checks`。每项包含 `id`、`phase`、`argv`、`cwd`、`status`、`durationMs`、`exitCode`、原因、修复提示及相对证据路径。状态为 `passed|failed|error|blocked|cancelled`；`error` 表示环境或编排问题，失败断言为 `failed`。总成功仅在所有选中必需项均为 `passed` 时成立，参数错误和所有其他总状态均返回非零退出码。

日志有大小上限，截断必须显式标记；stdout／stderr 分别保存。屏蔽 token、cookie、CSRF 和认证头，报告不保存环境变量全集或用户工作区内容。对每个结果标明实际执行命令，不把缓存、跳过或历史成功当作当前执行结果。

Studio `export_schemas.py --check` 在内存中生成预期 schema 并比较文件集合和内容，缺失、额外或漂移均失败；原有生成模式仍可显式使用。检查失败给出生成命令，但不自行执行。

### 4. CI 复用 profile，维护任务单独调度

新增 `.github/workflows/ci.yml`：在 PR、主分支更新及手动触发时运行，使用只读仓库权限，避免带高权限执行 PR 代码。Python 3.12 为首个完整验证基线；3.13、3.14 在同一入口执行 core 兼容检查。Studio 使用满足当前引擎约束的 Node 版本及锁定依赖，在 Linux CI 上验证；本地 macOS 执行同一旅程。兼容平台差异必须单独归因，不更新数值快照掩盖差异。

首版不做基于路径的跳过优化。完整基线 job 调用 `full`；额外 Python job 调用 `core`，不在 YAML 重新列出业务检查。Python、uv、Node、依赖和浏览器安装属于环境准备，可以在 YAML 配置，但验证选择由统一入口控制。缓存键包含平台、解释器与 lockfile 摘要。

结果与脱敏失败证据使用始终执行的上传步骤，保留 14 天。稳定的总结 job 传播上游失败，供维护者配置 required check。新增文件并不等于远端门禁已经启用：实施记录必须区分本地验证、实际 CI 结果和分支保护状态。

新增独立 `.github/workflows/maintenance.yml`，每周一次及手动执行只读维护扫描。该任务按根／Studio 锁文件及 web 构建顺序准备 schema 等检查所需环境，不运行浏览器旅程。这里只配置仓库 CI 调度，不创建 Codex 桌面提醒，也不发送外部消息。调度报告只作证据，不申请仓库写权限。

### 5. 浏览器验证采用 Playwright，限定三条旅程

用户已明确确认研究报告中的 P1；现有 `docs/core/development.md` 也要求 UI 变更验证真实浏览器流程。因此浏览器 E2E 是本变更的必需项，但只覆盖下列关键交互，静态与单元检查仍负责其他范围。

使用 `@playwright/test` 的隔离 fixture 与 Chromium，新增 `studio/web/playwright.config.ts`、`studio/web/e2e/`、独立 `e2e` npm script 和锁定开发依赖；从 Vitest 的发现范围排除 E2E 文件，给它们单独的类型检查入口。选择依据是 fixture 生命周期及浏览器诊断能力；参考 [Playwright fixtures](https://playwright.dev/docs/test-fixtures) 和 [trace viewer](https://playwright.dev/docs/trace-viewer)。不复用用户浏览器配置或常驻 Studio，不安装其他浏览器兼容矩阵。

每条旅程复制确定性的少量本地 OHLCV、策略和期望值到临时工作区。启动真实 Python CLI，传入 `--port 0 --no-open`；解析输出的 URL，在内存中完成正常 session 握手，不关闭 Origin、CSRF 或工作区验证。宿主 readiness 采用有截止时间的轮询，不采用固定 sleep 猜测。正常和异常路径均关闭宿主、worker、浏览器上下文，删除本次临时状态，不操作其他实例。

| 旅程 | 真实 UI 操作与成功证据 |
| --- | --- |
| 编辑并回测 | 通过编辑器修改并保存策略，发现参数，选择固定数据，执行真实 worker；确认源码 revision、成功状态、预期成交和报告一致 |
| 图表与导入导出 | 从成交记录定位图表，核对时间／标记联动与真实 canvas 渲染；导出后在独立只读 viewer 中打开，确认报告、图表及导航，执行入口不可用 |
| 失败及恢复 | 执行可控报错策略，在 UI 中观察失败及日志，关联同一次 run 的 phase／错误和可用产物；修改后产生新的成功 run，历史失败不会被覆盖为成功 |

不得替换 API、Monaco、图表或 worker 来通过这三条旅程。canvas 断言结合可见尺寸、可观测的定位变化和一次截图人工核验，不建立易碎的全屏像素基线。优先使用语义定位，必要时增加稳定的可访问标签或测试标识，不新增业务绕行接口。

依赖安装阶段可联网；测试运行只允许 loopback，使用本地字体、资产和数据。对浏览器及 worker 的外连建立失败检查，不能只拦浏览器请求便宣称全进程离线。保留现有安装检查中的离线运行证明。

失败默认保存截图、脱敏 DOM 摘要、控制台错误、请求状态及 run 标识、有限的 host／worker 日志与 manifest 摘要。失败可能发生在 manifest 生成前，证据包必须记录缺失原因，不能因缺少 manifest 丢掉原始失败。原始 trace 可能包含认证数据，默认不上传；只有实现可验证的脱敏后才将 trace 加入 CI 证据。截图和文本证据足以满足首版验收。

替代方案是继续人工浏览器检查或只补 HTTP 测试；两者不能提供可重复的渲染与交互回归，故保留现有测试并增加窄范围 E2E。

### 6. 架构规则依据现有导入图，不做全仓分层重构

新增 `scripts/check_architecture.py`、可审阅的规则数据及 `tests/test_architecture.py`。AST 扫描覆盖绝对／相对导入、函数内导入、别名、`TYPE_CHECKING` 和可静态解析的动态导入。无法静态解析的动态加载列入覆盖限制或明确受控入口，不声称静态检查能证明任意运行时导入安全。

首批规则：

1. core 运行时代码及其依赖声明不得依赖 `openbacktesting_studio`、FastAPI、uvicorn 或 Studio 资源；独立安装检查补充运行时证明。
2. `broker` 和 `data` 不得向 `strategy`、`simulation`、`optimizer`、`portfolio`、`runtime` 及其高层兼容转发入口增加依赖；保留当前 `data` 到指标类型等合法边。具体符号重导出须解析或明确记录，不能仅凭模块名漏过。
3. Studio 到 core 的现存内部接入逐条审阅并登记文件、目标和理由，新增内部依赖必须显式审阅；公开入口继续可用。不能把当前已有内部调用直接禁止，迫使本变更重构产品协议。

报告生成当前导入图，但不自动将所有现有边登记为允许规则。精确例外必须有责任角色、原因及移除条件，失效或过宽例外本身失败。错误包含规则 ID、文件／行、依赖边和修复建议。首版不禁止所有环，也不通过修改产品代码满足尚未论证的理想层级。

签名、pickle、事件、数值和结果契约仍调用现有测试；结构检查不能替代这些行为证明。规则测试以临时源码展示“新增违规边会失败”，避免仅重复实现本身。

### 7. 维护扫描产出可追踪证据，而非自动修复

新增 `scripts/doc_gardening.py`，复用验证定义中的只读文档、schema、登记、来源及架构检查，不递归调用整个 `full`。覆盖 `AGENTS.md`、维护文档、当前研究与计划的本地链接、生成物漂移、失效例外和规则覆盖；生成物正文由既有生成器负责。

每条 finding 包含稳定 ID、规则、文件、具体位置、证据、修复命令或责任角色及风险等级。ID 使用规则、相对文件和语义定位生成，不用运行时间或简单行号，避免插入一行后成为新问题。提供上次报告时输出新增、持续、已解决问题；没有历史报告时明确标记首次基线，不能声称出现新回归。

生成 JSON 和简短 Markdown 候选修复清单；文本修正、精确失效登记清理可标记为低风险，数值、执行顺序、schema、依赖和发布问题必须标记人工审阅。扫描不得执行修复命令，不调用远程创建 PR，不自动合并。

新增英文 `docs/core/harness-quality.md`，按导航、验证、浏览器、架构和维护五个领域记录证据入口、最后核验提交、已知缺口与责任角色，不编造质量分数。以检查耗时、重复 finding 和返工记录作为未来改进依据；没有历史数据时留空说明，不估算生产率。周期 job 可下载前次报告比较，找不到或下载失败时清楚区分，不得伪造“全部已解决”。

## Risks / Trade-offs

- 全量首次 CI 成本较高 → 首版选择完整信号，先记录耗时，再依据数据优化；不引入未经证明的路径筛选。
- 已有检查可能还有其他基线失败 → 先实际运行并分类，在对应任务内修复真实缺陷；不得删除检查或自动更新期望值求绿。
- 图表与编辑器等待易抖动 → 固定数据、视口、环境和语义等待；不默认重试掩盖不稳定，不做宽泛像素匹配。
- 真实宿主包含认证材料 → 只使用合成工作区，证据采集时脱敏，上传前扫描，原始 trace 默认不上传。
- 静态导入分析不能涵盖任意动态执行 → 限定规则覆盖、记录受控入口，保留独立安装和真实 worker 测试。
- 中文文档摘要随编辑变动 → 对本次最终产物显式更新精确摘要，验证模式不自动批准新的内容。
- Linux 与 macOS 文件系统及进程行为不同 → CI 与本机分别记录验证结果；不由 POSIX 成功推断 Windows 支持。

## Migration Plan

1. 记录现有检查结果，清理确定失效的语言登记；补导航与统一入口并验证失败传播。
2. 加入 CI、schema 只读检查和双包验证，确保本地及 CI 使用同一检查集合。
3. 建立隔离浏览器 fixture，逐条完成三条旅程及故障注入验证，再纳入 `studio`／`full` 必需项。
4. 审阅实际依赖图，加入少量架构规则、维护扫描和周期 workflow，完成质量证据记录。
5. 从干净检出执行 `full`，核对源码未被验证过程改写、产物不含凭据、临时进程已清理。按实际结果更新实现记录及中文摘要；全部任务完成后另行归档本变更。

各阶段可独立提交便于回滚，但不能将只完成 P0 标为整体完成。回滚只撤销本变更新增入口、配置和开发依赖，保留用户文件与历史运行产物；不恢复失效例外，也不恢复已删除的历史 OpenSpec。
