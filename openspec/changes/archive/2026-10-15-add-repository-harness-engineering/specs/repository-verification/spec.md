## Purpose

提供本地与持续集成共享的验证接口和结果协议，将已有行为、文档、架构与分发检查组合成可重复且可诊断的检查集合，确保环境错误、跳过、超时和真正通过不会混淆。

## ADDED Requirements

### Requirement: 统一入口提供明确的验证集合

验证入口 MUST 支持 `docs`、`core`、`studio`、`full` 四种 profile，默认执行 `full`；未知 profile 必须失败。`full` MUST 覆盖前三者及双包分发与独立安装检查，重复检查按稳定 ID 去重；文档和核心 profile 不得要求 Node 或浏览器。

#### Scenario: 使用默认验证范围

- **WHEN** 调用者不提供 profile
- **THEN** 入口选择 `full`，不根据改动路径静默缩小范围

#### Scenario: 拒绝未知验证范围

- **WHEN** 调用者提供未知 profile
- **THEN** 入口返回非零状态和可用值，不运行不确定的检查集合

#### Scenario: 检查集合完整可见

- **WHEN** 执行任意 profile
- **THEN** 结果列出全部选中检查、实际执行状态和显式排除项，未执行或可选慢测试不得计为通过

### Requirement: 验证环境与产物身份可复现

验证 MUST 使用对应包的锁文件和必要依赖，记录解释器、工具版本及锁摘要；Studio 必须先获得匹配的构建资产。缺少工具、依赖或浏览器必须失败并提供准备说明，不能自动放宽验证范围。分发产物版本必须来自当前项目元数据。

#### Scenario: 缺少浏览器或 Studio 环境

- **WHEN** 执行 Studio 验证但必要运行环境不可用
- **THEN** 报告环境错误和修复命令，整体非零，浏览器旅程不得被标记通过

#### Scenario: 包版本变化

- **WHEN** 当前项目元数据中的包版本更新
- **THEN** 分发检查选择本次构建的对应产物，不依赖旧版本硬编码文件名

### Requirement: 结果协议和失败传播可靠

每次验证 MUST 输出版本化 JSON 和可读摘要，包含运行身份、profile、提交与 dirty 状态、环境、时间及每项检查的 ID、阶段、命令、目录、状态、耗时、退出码、原因和证据。只有全部选中必需项通过才可返回零。

#### Scenario: 检查失败阻断依赖项

- **WHEN** 某必需检查失败
- **THEN** 总结果非零，依赖项明确为 `blocked`，可继续执行的独立检查保留自身结果

#### Scenario: 超时或用户取消

- **WHEN** 检查超过截止时间或运行被取消
- **THEN** 入口停止本次启动的进程，保存部分结果及原因，返回非零且不覆盖为通过

#### Scenario: 重跑失败检查

- **WHEN** 调用者再次执行此前失败的验证
- **THEN** 生成可区分的 attempt 或运行记录，保留首次失败证据，不以重跑覆盖历史结果

### Requirement: 验证不得静默修改受保护内容

检查 MUST 不修改受版本控制的源码、锁文件、schema、manifest、fixture 和数值基线；允许在明确的输出或忽略目录生成构建与诊断产物。入口 MUST 区分运行前的用户改动与本次新增修改，发现越界写入即失败，不自动重置工作区。

#### Scenario: 验证在已有未提交改动上运行

- **WHEN** 工作区在检查前已有未提交源码修改
- **THEN** 验证保留这些修改，报告 dirty 状态，不要求 reset 以继续

#### Scenario: 检查器意外改写生成文件

- **WHEN** 验证过程中已跟踪 schema 或基线发生额外变化
- **THEN** 总结果失败并指出文件，文件保留供审阅，入口不自动接受或撤销改动

### Requirement: Studio schema 支持只读漂移检查

Studio schema 检查 MUST 比较当前模型生成的预期文件集合及内容；缺失、额外或漂移必须失败并给出显式生成指引，不在检查模式写入文件。

#### Scenario: schema 与模型不一致

- **WHEN** 修改协议模型而未更新 schema，或 schema 文件集合发生错误
- **THEN** 检查返回非零并列出差异，检查前后的 schema 字节保持一致

### Requirement: CI 使用统一定义并保留失败证据

第一方 CI MUST 调用同一验证入口而不复制检查选择逻辑，覆盖 PR 和主分支更新。CI MUST 将任意必需任务失败传播到稳定的总结状态，在失败时保存有限期诊断产物；对贡献代码只使用完成验证所需的只读权限。

#### Scenario: 本地和 CI 验证相同 profile

- **WHEN** 两个环境在同一提交和锁文件上执行同一 profile
- **THEN** 选中检查 ID 集合一致，环境差异在报告中明确记录

#### Scenario: CI 中的检查失败

- **WHEN** 某个必需 CI 任务失败或被阻断
- **THEN** 总结状态失败，已产生的脱敏诊断仍被保存，不因后续上传成功而变为通过

### Requirement: 证据不泄露认证材料

公开保存或上传的验证证据 MUST 排除启动 token、session cookie、CSRF、认证头、完整环境变量和非 fixture 用户数据；截断或缺失证据必须有说明。

#### Scenario: 日志中出现测试凭据

- **WHEN** 子进程或浏览器诊断包含认证字段
- **THEN** 对外报告中这些值被移除或替换，无法安全处理的原始产物不上传，并说明证据缺失原因
