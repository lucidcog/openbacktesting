## Purpose

通过可重复的只读扫描识别知识入口、生成物、语言登记、来源和架构约束的漂移，并形成稳定的问题记录及候选修复说明，使重复错误能够被追踪和转化为检查，而不依赖聊天记忆或自动改写基线。

## ADDED Requirements

### Requirement: 维护扫描复用已定义检查并保持只读

维护扫描 MUST 复用统一验证中的文档、schema、登记、来源及架构检查定义，覆盖当前研究和计划的本地引用。扫描只输出报告，不执行修复命令，不静默更新摘要、生成文件、测试基线或用户源码。

#### Scenario: 检出失效引用和生成物漂移

- **WHEN** 当前知识入口引用失效文件，或受检查生成物与源不一致
- **THEN** 扫描返回失败与可定位的问题，源文件和受保护产物保持原样

### Requirement: 问题标识与跨次比较稳定

扫描报告 MUST 为 finding 提供稳定 ID、规则、相对文件、语义定位、证据、风险等级和修复建议。提供可用历史报告时必须区分新增、持续和已解决；缺少或无法读取历史时必须标明状态，不能推断问题已解决。

#### Scenario: 插入无关文本

- **WHEN** 同一问题前增加无关行而语义定位不变
- **THEN** finding 保持相同 ID，并在与旧报告比较时归为持续问题

#### Scenario: 首次扫描或历史不可用

- **WHEN** 没有上次报告，或上次报告不可读取
- **THEN** 输出分别说明首次基线或历史读取错误，不生成虚假的改进趋势

### Requirement: 周期维护生成有限期可审阅证据

第一方维护 workflow MUST 支持每周及手动执行，保存 JSON、可读摘要与候选修复清单，保持只读权限且不自动发布外部消息或修改仓库。发现问题或扫描环境失败时必须返回相应非成功状态。

#### Scenario: 周期扫描发现问题

- **WHEN** 定期扫描识别文档漂移或失效例外
- **THEN** 保存可下载的诊断与修复建议，job 状态反映失败，不推送提交、创建 PR 或自动合并

### Requirement: 候选修复按风险分级

维护报告 MUST 区分可局部审阅的文档／失效登记修复和需要维护者判断的交易数值、时序、schema、依赖及发布问题。修复建议不能视为执行授权，重复 finding 应能链接到后续规则或回归测试。

#### Scenario: 发现数值或契约差异

- **WHEN** 维护扫描发现结果基线、公开 schema 或依赖身份不一致
- **THEN** 标记需要人工判断，不建议自动刷新基线求得通过

### Requirement: 质量记录基于真实证据

仓库 MUST 维护导航、验证、浏览器、架构和持续维护五类能力的证据入口、最后核验提交、已知缺口与责任角色。无历史数据时必须注明未知，不填造覆盖率、生产率或改进分数。

#### Scenario: 新能力首次落地

- **WHEN** 新增浏览器或架构验证并首次运行
- **THEN** 质量记录关联实际命令和结果，历史趋势保持未知，不把计划完成度当作测试通过率
