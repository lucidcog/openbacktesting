## Purpose

为 Studio 的编辑、执行、图表、结果传递和失败恢复提供可重复的真实浏览器证据，连接现有宿主与真实执行流程，并以隔离环境、可诊断失败和可靠回收避免测试影响用户工作区。

## ADDED Requirements

### Requirement: 验证使用真实且隔离的完整应用

浏览器验证 MUST 使用构建后的 Studio 页面、真实宿主、真实 worker、本地确定性数据和独立临时工作区；不得以模拟 API、编辑器、图表或 worker 替代关键旅程。宿主只监听 loopback，动态分配端口，并保持现有认证和工作区安全边界。

#### Scenario: 启动一次独立旅程

- **WHEN** 浏览器验证开始
- **THEN** 创建独立工作区与浏览器上下文，通过正常握手进入真实宿主，不访问用户浏览器配置、常驻实例或私人数据

#### Scenario: 运行时出现外部依赖

- **WHEN** 已安装测试依赖后，浏览器或策略进程尝试访问非 loopback 网络
- **THEN** 验证失败并报告目标，不通过远程资产或数据继续生成成功结果

### Requirement: 编辑策略并运行的旅程可验证

验证 MUST 经真实编辑器保存策略、发现参数、选择固定数据并发起回测，核对保存的源码身份、执行成功状态和明确的成交及报告期望；按钮可点击或页面可加载本身不足以视为通过。

#### Scenario: 保存后的策略决定回测结果

- **WHEN** 测试通过界面修改、保存并运行 fixture 策略
- **THEN** 新 run 对应保存后的 revision，真实 worker 完成，报告显示与独立期望一致的成交和结果

### Requirement: 图表与结果传递的旅程可验证

验证 MUST 覆盖成交定位与真实图表联动，以及结果导出后在独立只读查看模式中的报告、图表和导航。只读模式不得提供策略执行能力。

#### Scenario: 成交定位到图表

- **WHEN** 用户在固定成交报告中选择一条记录
- **THEN** 真实渲染的图表定位对应时间或 bar，相关标记和可观察的界面状态一致

#### Scenario: 导出结果后只读查看

- **WHEN** 通过 UI 导出结果并在独立只读查看实例中打开
- **THEN** 报告与图表保留对应结果和导航关系，修改及执行入口不可用

### Requirement: 失败诊断与恢复的旅程可验证

验证 MUST 执行可控失败策略并检查界面状态、日志及关联运行证据，再通过界面修复和重跑；失败记录不得被新运行覆盖为成功，错误也不得以空报告伪装成功。

#### Scenario: 失败后修复重跑

- **WHEN** fixture 策略报错，随后用户修改保存并再次运行
- **THEN** 旧 run 保留失败身份及可用诊断，新 run 具有新的身份、源码 revision 和成功结果，二者在 UI 与证据中可区分

### Requirement: 失败证据有界且可靠回收资源

浏览器验证 MUST 设置启动与执行截止时间，在失败时保存截图、脱敏界面或请求诊断、run 关联信息和可用进程日志。证据缺失应有原因。成功、失败、超时或取消均必须关闭本次宿主、worker 和浏览器，并回收临时状态，不干扰其他实例。

#### Scenario: 宿主尚未就绪即失败

- **WHEN** 宿主启动超时或提前退出，尚无 run manifest
- **THEN** 验证保留原始退出或超时原因及已有日志，说明 manifest 不存在并返回非零，不再无限等待

#### Scenario: 旅程中断

- **WHEN** 浏览器断言失败或测试被取消
- **THEN** 只回收本次实例的进程与临时数据，已有用户工作区和其他监听端口不受影响

#### Scenario: 证据包含认证数据

- **WHEN** 采集日志、请求诊断或 trace
- **THEN** 只有经过脱敏的内容可进入共享产物；不能安全脱敏的原始 trace 不上传，不因证据采集失败丢失原始测试错误
