# Plot declarations and export

`Strategy.plotting` produces independent plotting data, and `export_result(result)` exports a frozen `PlottingResult`. The core does not render, write chart files, or launch browsers. Desktop Worker execution and frontend rendering remain unconnected.

## Author calls

Create panes in `init`, declare layers from market-data or indicator handles, and add runtime markers in `next/on_order/on_fill`. The tested author example covers main-pane moving averages, a separate MACD pane, histograms, horizontal levels, fills, static colors, per-bar background/candle colors, and market-data/indicator handles:

[Complete source](../../../examples/strategies/plotting.py)

All declaration `id` and `title` values may be omitted. Optional `pane` defaults to the main pane independently of prior calls. `pane()` explicitly creates a separate pane and returns `PaneRef`; reusing the reference shares its pane and automatic vertical axis. Strings cannot replace references.

Omitted IDs are generated by run, reference type, and declaration order as `auto:type:sequence`; collection switches do not affect identical call sequences. Omitted titles use the final ID; explicit empty titles remain empty, and duplicate titles are allowed. Empty IDs, duplicate IDs, `main`, and explicit IDs prefixed with `auto:` are rejected. Source identity is engine-generated; forged and cross-run references are invalid.

## Sources and layers

| Call | Meaning and constraints |
| ---- | ----------------------- |
| `line(handle)` | Complete single-channel market data or indicator; defaults to a line, with `style="step"` for steps |
| `histogram(source)` | Histogram; finite `baseline=0` participates in automatic range calculation |
| `level(value)` | Finite horizontal constant without allocating a complete numeric array |
| `fill(lower, upper)` | Two PlotRef objects on the same pane/axis; units and offsets must be compatible |
| `marker(...)` | Add one marker in a runtime callback independently of actual fills |

Select a channel first for multi-output indicators, such as `macd.histogram`. Handles must belong to the current run; shortened, reversed, or displaced time slices raise errors. Multiple layers using one handle share a source. Plotting registers no new calculation indicators and changes neither callbacks, cache keys, nor indicator values.

Numeric layers accept only complete single-channel market-data/indicator handles from this run and static colors; arrays and pandas Series cannot serve directly as sources. Real zero remains zero; NaN/Infinity exports as null with a recorded reason. Authors must explicitly convert booleans to numbers. Markers may be added in next and fill/order notifications, including terminal notifications; on_start/on_finish, outside execution, and after closure are prohibited.

Static colors accept Color or six/eight-digit hexadecimal strings. Omitted colors or None select the consumer palette; arrays, references, and callbacks cannot be colors. Default `gap_policy="break"` breaks gaps; `"connect"` permits connecting lines. Neither interpolates nor changes sources. `offset_bars` is a display shift without changing raw data, visibility, or trading timing; consumers clip display points beyond the historical axis.

Marker shapes are `circle/square/triangle_up/triangle_down`; positions are `above_bar/below_bar/price`, with finite price required for price positioning. `anchor_bar` may target a valid current or past bar, never a future bar. `knownAtBar` records creation time and cannot be overridden. Text is plain text and must not be executed as HTML by consumers.

## Color values and strings

Import `Color, colors` from the package root. The 17 presets such as `colors.RED` are already Color objects. Construct values with `Color.from_hex("#22aa44")`, `Color.rgb(34, 170, 68, transparency=40)`, or `Color(34, 170, 68, alpha=153)`. Presets are fixed to verified Pine v6 values, such as BLACK=`#363A45FF`, independent of theme; see the [color API](../reference/colors.md) for all presets.

Color is immutable, compares by RGBA, supports hash/pickle, and is not implicitly equal to strings. `red/green/blue/alpha` are read-only integers. `with_transparency(40)` returns a new value replacing transparency without modifying the original. Transparency 0 is opaque and 100 fully transparent, opposite to alpha. Transparency is quantized once as `floor(255 * (100 - t) / 100 + 0.5)`; 50 yields alpha=128 and reverse-calculated `transparency` about 49.8039, without retaining the original percentage.

Channels accept only native int values 0–255; transparency accepts native finite int/float values 0–100. Both reject bool, and NumPy scalars require explicit conversion. Invalid types raise TypeError; out-of-range or malformed values raise ValueError, wrapped as InputError/PlottingError at inputs/plotting boundaries. Strings support only six/eight-digit hexadecimal, without CSS names, shorthand, whitespace, or newlines.

All plotting color entry points output uppercase eight-digit `#RRGGBBAA`, adding FF to six-digit values; `to_hex()` and `str(color)` use the same format. Output text and payload hashes change for prior lowercase plotting strings, but RGBA is unchanged; readers still accept historical casing. Do not JSON-encode Color directly: input snapshots and plotting exports already convert it. Declare static colors in init and compute per-bar dynamic colors in next; Color arrays and color indicator handles are unsupported.

## Current-bar background and candle colors

`bg_color(color, *, pane=None)` sets the current background of the main or an existing separate pane; `bar_color(color)` sets original main-pane candle colors. Both return None and are callable only in `next()` and its synchronous branches, loops, and helpers. init/on_start/on_finish/on_order/on_fill, terminal notifications, and post-run calls are rejected. Required color accepts Color, `#RRGGBB`, `#RRGGBBAA`, or None; arrays, handles, callbacks, CSS, and omission are rejected.

The last write to the same `(kind, pane, bar)` wins. None explicitly clears that key's override; absent another call, an earlier write on the current bar remains, but new bars do not inherit it. A transparent color with alpha `00` is still a color rather than clearing. Pane backgrounds are independent; candle coloring covers bodies, wicks, and borders together. Colors affect neither market data nor automatic vertical axes. Backgrounds cover only the pane's plot area within the current horizontal bar slot, below data layers, excluding text and axes.

Color calls create no source, plot, ID, or reference. Colors may be written during actual `next()` calls on first/last bars and while indicators are invalid. Bars without next due to bankruptcy or exceptions, and periods after termination, are not filled in. Authors retain persistent state and resend it on each actual next. These Python call rules are a local contract, not Pine global-call syntax.

`colorEvents` records `kind/pane/axis/anchorBar/knownAtBar/phase/sequence/color` in call order. kind is `background/bar`, axis is `bars`, phase is `next`, and both bar positions are equal. sequence increases independently within this run's color domain, without interleaving marker or trading sequences. Explicit clears output null. Consumer replay first limits knownAtBar, then selects the last write per target and bar; missing events do not imply automatic color filling.

New results always include colorEvents. Nonempty events require `bar-coloring-v1`, including clear-only events. New protocol consumers and snapshot exports retain reading support for colorless `1.0.0`; the new format is `1.1.0`. Old closed schemas are not guaranteed to read the new format. Future consumers unable to support colors, alpha, and all three candle parts must reject the required capability instead of silently degrading. This repository currently supplies data without rendering.

## Host export

[Complete source](../../../examples/advanced/plotting_export.py)

Successful results store an immutable, pickleable pure-value tuple snapshot in `attrs["plotting_result"]`; the entire attrs remains strict-JSON encodable. Export neither reads `_strategy` nor executes user code again. Changes to returned dictionaries, native trade tables, or later runs do not affect old snapshots. Failed runs publish no success snapshot and close their references.

New payload version `1.1.0` contains axes/panes/scales/sources/plots/fills/markers/colorEvents/market/tradingFacts/execution, capabilities, and diagnostics. Market data retains five columns; fills and accounts directly copy existing ledgers. Normal `bar` and end-of-run `terminal` account records for the last bar are retained separately. User signals and actual fills may occur on different bars.

Result `sources` is an internally generated numeric table referenced by layers, not an author declaration entry point. Values and masks align by bar position. Complete indicators with `samplingMode="offline"` may cover history beyond early termination; markers record actual calls only. `execution.processed/strategyNext` identifies processing and next calls separately; execution range cannot be inferred from the full cursor restored at the end.

Aware indexes use UTC nanosecond integer strings plus the original timezone; naive dates use `naive-datetime` labels and ordinary scalar indexes use `ordinal` labels. UTC is not guessed and bars are not fabricated. Integers exceeding JavaScript's safe range encode as decimal strings; plotting consumers decide display precision loss, but must not convert timestamps to floats before association.

## Automatic vertical axes and protocol boundaries

Authors do not create scales or specify bounds. The main pane shares a price axis; each separate pane has an independent automatic axis. Consumers compute ranges from currently visible valid layers, OHLC extremes, visible levels, and histogram baselines, excluding invalid, not-ready, and invisible layers. Constant ranges need expansion and empty states need default ranges. The core emits no viewport-dependent fixed min/max.

The sole cross-language schema is `packages/protocol/schemas/plotting-result.schema.json`. The protocol package's Python `validate_plotting_result` and TypeScript `validatePlottingResult` validate fields, reference ownership, masks, timing, and budgets, returning degradation diagnostics for unknown optionalFeatures. Unknown requiredFeatures and unsupported versions are rejected. The independent core does not depend on the protocol package.

The payload contains no runId, file paths, or permissions and is not inlined into 1 MiB control frames. Future hosts must bind runs, persist artifacts, and integrate frontends separately; schema availability does not mean `strategy.execute/chart.render` is available.

## Collection switches and resource budgets

`Backtest(..., plotting=False)` retains declaration references, identity, type, and phase checks without retaining historical visual payloads or offering exportable snapshots. Color calls still validate individually and consume events: repeated colors, transparent colors, and None all count without deduplication by final override count. grid and supported SAMBO candidates use this mode automatically; only the best-parameter rerun follows user settings. Scoring functions may depend only on computed results.

`Backtest(..., plotting_limits=PlottingLimits(...))` adjusts positive-integer budgets:

| Setting | Default | Counting rule |
| ------- | ------: | ------------- |
| panes | 32 | Includes the main pane |
| plots | 256 | Includes fill |
| points | 10,000,000 | Points in each unique dense source plus five market-data columns and two execution-mask columns; layers sharing a source do not count twice |
| events | 1,000,000 | Total color calls, markers, fills, and account records |
| text | 1,048,576 | UTF-8 bytes of author IDs, titles, units, and marker text |
| bytes | 268,435,456 | Compact UTF-8 JSON export bytes |

Exceeding limits raises `PlottingError` with code `PlottingLimitExceeded`, without removing points or silent truncation. The byte budget is checked on explicit export; original trading results remain readable after it is exceeded. Other stable codes include `invalid-phase`, `invalid-reference`, `duplicate-id`, `misaligned-source`, `missing-snapshot`, and `unsupported-version`.

Run `uv run --locked python -m pytest tests/test_plotting.py tests/test_bar_coloring.py` to verify snapshots, exports, resource limits, and coloring boundaries. This extraction adds no performance benchmarks or cross-hardware thresholds.

## Scalar gradients

`Color.from_gradient(value, lower=..., upper=..., lower_color=..., upper_color=...)` linearly interpolates unpremultiplied RGBA bytes between two Colors, rounding half-byte values upward and clamping out-of-range values to endpoints. Endpoints and results are immutable. Numeric inputs accept only native finite int/float, rejecting bool; bounds must strictly increase, and endpoints reject strings and None. Explicitly convert indicator scalars with `float(...)` after checking valid. Alpha is interpolated too; this is neither perceptual color-space interpolation nor screen compositing. Returned colors reuse existing line/bar_color/bg_color calls and the export protocol. See the [runnable gradient example](../../../examples/strategies/local_value_helpers.py).
