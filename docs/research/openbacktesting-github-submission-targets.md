This is broad coverage, **not a claim that every GitHub directory has been found**.
- Recommendations are editorial judgments. File contents, explicit rules, archive flags, commit dates and sampled merge events are facts. A quiet default branch suggests uncertain response prospects; it does not prove abandonment. A recent automated commit or `pushed_at` does not prove active human curation. Stars are an audience/eligibility signal, not quality evidence.

The public [development provenance section](https://github.com/lucidcog/openbacktesting/blob/777a26b83d37500d817cf6f721ab8a2a21447b80/docs/core/development.md#provenance-and-behavioral-boundaries) and [source manifest](https://github.com/lucidcog/openbacktesting/blob/777a26b83d37500d817cf6f721ab8a2a21447b80/source-manifest.json) preserve earlier source evidence; the license wording here reports the current public declaration and is not an independent provenance or licensing determination.

The correct category is **historical, bar-by-bar, single-asset Python backtesting**. One run uses one settlement currency. It does not supply live execution, a multi-asset account, a chart renderer, a Pine converter, stock-borrow interest or a funding-fee model. Those limits matter especially for institutional, crypto, regional-market and agent directories. A Portfolio report does not turn it into a portfolio-allocation engine. [Supported boundaries](https://github.com/lucidcog/openbacktesting/blob/777a26b83d37500d817cf6f721ab8a2a21447b80/docs/core/limitations.md).

That demonstrates new public distribution, not the age of all underlying implementation. The README gives source installation and explicitly does not assume a PyPI release; this research did not establish a public PyPI release, external adoption, comparative speed or production readiness. Do not imply those facts in submissions. [Repository metadata API](https://api.github.com/repos/lucidcog/openbacktesting), [source installation instructions](https://github.com/lucidcog/openbacktesting#quick-start).
